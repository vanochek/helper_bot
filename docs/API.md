# API без AI

Базовый адрес: http://127.0.0.1:8000/api/v1. Интерактивная схема: /docs.
В .env можно задать APP_ORIGIN — точный origin интерфейса без завершающего слеша.
Для HTTPS задайте https://ваш-домен: cookie автоматически получает Secure.
Значение по умолчанию: http://127.0.0.1:8000. localhost считается другим origin.
Все POST/PATCH требуют заголовок Origin с этим значением, включая запросы CLI.
Cookie должен сохраняться клиентом и отправляться с последующими запросами.

| Метод и путь | Назначение |
|---|---|
| POST /session | Создать сессию: {"timezone":"Europe/Moscow"}; существующая сохраняется |
| GET /session | Узнать текущий часовой пояс |
| PATCH /session | Изменить timezone, не меняя сохранённые моменты времени |
| POST /entries | Создать task, reminder или meeting; ответ 201 после commit |
| GET /entries | Список, фильтрация и поиск |
| GET /entries/{id} | Одна запись владельца; отсутствующая или чужая — 404 |

Пример тела создания:
```json
{"kind":"meeting","title":"Встреча с командой","scheduled_at":"2026-10-30T15:00:00+03:00"}
```
Для задачи без времени: {"kind":"task","title":"Отчёт","scheduled_on":"2026-10-30"}.
Для напоминания kind=reminder, точное scheduled_at обязательно.
Владелец, статус и служебные поля не принимаются от клиента.

GET /entries?start=2026-10-28&end=2026-10-29 — локальные сутки пользователя.
Обе границы обязательны вместе; end не включается. Срок встречи определяется началом.
GET /entries?q=презентация — поиск словоформ по названию и подробностям.
Параметры периода и q можно сочетать. Поиск — все значимые слова запроса, без AI.
limit: 1–100 (по умолчанию 50), offset: 0–10000. Порядок: созданные позже первыми,
затем UUID; это не рейтинг релевантности и не календарная сортировка.

Ошибки: 401 — нет действующей сессии; 403 — неправильный/отсутствующий Origin;
404 — запись недоступна; 422 — некорректные параметры; 503 — ошибка хранилища.
Ключи, токены и внутренние ошибки БД не возвращаются в ответах.
Защита от повторного POST появится на этапе 6: сейчас повтор создаёт новую запись.
Публичный доступ пока не подготовлен: ограничения нагрузки и эксплуатационная
защита входят в этапы 9–10.
