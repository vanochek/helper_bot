# Текстовый ассистент

Реализованы этапы 5–7: адаптер OpenAI Responses, интерпретация одного действия,
уточнения, отмена, атомарная защита от повторов и браузерный текстовый интерфейс.

## Настройка

В локальном .env укажите OPENAI_API_KEY и OPENAI_MODEL — доступную вашему проекту
модель с поддержкой Responses API и Structured Outputs. Значение модели намеренно
не выбрано автоматически: доступность зависит от API-проекта. Перезапустите сервер.
Ключ не вводится в браузер и не добавляется в Git. Без настройки сервер возвращает
понятный 503, а не подставляет фиктивного ассистента.

Запуск: python dev.py bootstrap, затем python dev.py serve. Откройте
http://127.0.0.1:8000. Для другого адреса задайте APP_ORIGIN точно по адресу страницы.
Браузер предлагает свой часовой пояс при первом открытии; существующая сессия
сохраняет выбранную зону. Текст сообщения отправляется OpenAI для интерпретации.

## Протокол

POST /api/v1/chat/messages принимает {"request_id":"UUID","text":"Сообщение"}.
Нужны cookie и корректный Origin. Текст: 1–2000 символов. Ответ содержит status,
text и entries с сохранёнными данными. Статусы: completed, needs_clarification, cancelled.
GET /api/v1/chat/messages возвращает последние 50 сообщений только текущей сессии.

Один незавершённый диалог на сессию, общий между вкладками. Контекст хранится в БД,
живёт 30 минут и ограничен шестью пользовательскими сообщениями. Исходные now и
часовой пояс фиксируются, чтобы «завтра» не изменилось во время уточнения.
Слова «Отмена», «Отмени», «Отменить» очищают черновик без обращения к AI.
Прошедший срок требует отдельного «да»; подтверждается сохранённый кандидат,
а не новая интерпретация моделью. Завершённые диалоги не передаются модели снова.

Повтор одного request_id и текста возвращает сохранённый ответ без AI и без повторного
действия; другой текст с тем же ID даёт 409. Блокировка строки сессии сериализует
параллельные сообщения. Запись, ответ и черновик фиксируются одной транзакцией.
При сбое commit всё откатывается. Ожидание блокировки ограничено 5 секундами;
вызов OpenAI — 25 секундами, автоматические повторы SDK отключены.
При потере ответа клиент повторяет прежний ID, в том числе после перезагрузки:
незавершённый запрос временно хранится в sessionStorage текущей вкладки.
Прямой POST /entries остаётся низкоуровневым API без этой защиты — UI использует chat.

## Границы и проверка

LLM выдаёт типизированное намерение, не SQL и не ответ о сохранении. Сервер разрешает
только create/list/search/clarify, валидирует даты и поля, подставляет владельца из
сессии. Подтверждение и список формирует приложение из результатов БД.
Responses вызывается с store=false; это не обещание отсутствия хранения данных
провайдером по его политикам. Локально сообщения и ответы хранятся до удаления БД;
политика очистки и эксплуатационные лимиты остаются этапом 9.

Интерфейс выводит пользовательский текст через textContent, не innerHTML.
Имеются история, состояния ожидания, повтор, отмена и отображение найденных записей.
Результаты поиска ограничены 50 записями; голос и озвучивание реализованы, см. VOICE.md.

Автотесты подменяют только AI-адаптер, используя настоящие PostgreSQL и HTTP-обработчики.
Проверены атомарность, конкурентные повторы, уточнение, отмена, поиск, период,
изоляция истории, отказ AI и конфигурация вызова SDK. Реальный вызов OpenAI пока
не проверен: в локальном окружении нет ключа. До настройки и живой приёмки качество
понимания свободных формулировок не считается подтверждённым.

Контракт SDK сверялся с официальной документацией:
https://developers.openai.com/api/docs/guides/structured-outputs

Без ключей используйте AI_MODE=demo. Поддерживаемые шаблоны и переключение — DEMO.md.
