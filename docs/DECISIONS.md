# Решения

- Python 3.14: уже установлен, совместимость подтверждается uv.lock и тестами.
- Версии из архитектурного предложения не являются установленными: источник фактических Python-зависимостей — uv.lock.
- PostgreSQL 18 в Docker; порт только localhost:55432.
- Модели AI пока не закреплены: доступность в API проверить при реализации адаптера.
- CI/CD не добавляется согласно архитектурному ограничению.
- Учётные данные локально генерируются bootstrap; API-ключ предоставляет владелец перед интеграцией AI.

## Этапы 1 и 2

- Владелец — анонимная браузерная сессия, без аккаунтов; хранится SHA-256 токена.
- Одна таблица entries согласно архитектурному предложению; UUID генерирует сервер.
- Ограничения времени и типов действуют и во входной модели, и в PostgreSQL.
- Зона проверяется по IANA при создании сессии; точные времена без зоны отклоняются.
- Полные составные индексы владельца/времени, владельца/даты и владельца/создания
  пока предпочтены частичным: проще схема, включают записи без срока.
- Поисковый GIN-индекс откладывается до реализации поискового запроса на этапе 3.
- Транзакции принадлежат прикладному сервису, репозиторий не делает скрытый commit.
- Cookie, Origin и определение владельца из HTTP реализуются до публикации предметного API.
