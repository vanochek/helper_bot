# Развёртывание и комплект сдачи

Публичного адреса пока нет: владелец сообщил, что сервер и домен не выбраны.
Ни DNS, ни внешние серверы не изменялись. Код подготовлен для Linux-сервера с Docker Compose.

## Локальная проверка production-конфигурации

```powershell
python dev.py deploy-init
python dev.py deploy-up
```

Создаётся deploy/.env с уникальными паролями, отдельные контейнеры helper-production
и отдельный volume базы. Настройки разработки не меняются. Повторный deploy-init
отказывается перезаписывать секреты. В тестовом режиме адрес https://localhost:18443,
порт HTTP 18080. Caddy выдаёт локальный сертификат своей CA: браузер не доверяет ему
автоматически. Проверка с отключением доверия допустима только локально; для работы
микрофона используйте доверенный сертификат либо обычный localhost-режим разработки.
Остановка без удаления данных:
`docker compose --env-file deploy/.env -f deploy/compose.yaml down`.

## Публикация после выбора сервера

1. Подготовить Linux-сервер, Docker Engine и Compose, Git, открыть входящие 80 и 443.
2. Направить DNS A (и AAAA только при настроенном IPv6) домена на сервер.
3. Клонировать репозиторий и зафиксировать выпускаемый commit.
4. Создать deploy/.env командой deploy-init; задать DOMAIN=имя-домена,
   APP_ORIGIN=https://имя-домена, HTTP_PORT=80, HTTPS_PORT=443, BIND_HOST=0.0.0.0.
5. Заполнить OPENAI_API_KEY, OPENAI_MODEL, OPENAI_STT_MODEL; установить бюджет/квоты
   API-проекта. Защитить файл правами доступа владельца. Пароли БД оставлять hex,
   как у генератора, либо корректно URL-кодировать перед использованием в URL.
6. Запустить deploy-up. Мигратор завершает Alembic до запуска приложения и выдаёт
   helper_app только SELECT/INSERT/UPDATE/DELETE на три таблицы. CREATE и владение
   схемой остаются у helper_owner. Порты БД и приложения наружу не публикуются.
7. Caddy получает и обновляет публичный сертификат, если DNS и порты настроены.
   Проверить https://домен/health/ready без отключения проверки сертификатов.
8. Пройти живую приёмку из OPERATIONS.md, проверить микрофон и голос на устройстве.
   Только после этого добавить фактическую публичную ссылку в README.

## Ограничения профиля

Один процесс приложения. Nginx ограничивает общий поток (10 запросов/сек., burst 30),
маршруты AI (40/мин., burst 10), соединения (32), размер тела (10 МиБ) и тайм-ауты.
Встроенные IP-лимиты приложения видят адрес gateway и становятся общими: forwarded
headers намеренно не принимаются. Это консервативный предел демо, не многопользовательская
распределённая платформа. Денежный бюджет обязательно ограничивать у провайдера.

Образы PostgreSQL, Nginx и Caddy закреплены digest проверенных локально образов.
Базовые образы сборки Python/uv закреплены веткой/версией; обновление требует пересборки
и повторной приёмки. Python-зависимости
зафиксированы uv.lock. Контейнер приложения read-only, без capabilities, UID 10001.
Секреты не попадают в build context, но доступны администраторам Docker как environment.
Логи Compose могут содержать сведения TLS/прокси: хранить с ограничением доступа.

## Обновление и восстановление

До обновления: `python dev.py backup --production`. Проверка восстановления:
`python dev.py restore-check --production` (новая копия) либо
`python dev.py restore-check backups/имя.dump --production`.
Для сохранения восстановленной БД: `python dev.py restore-new backups/имя.dump --production`.
Эти команды выбирают Compose-профиль deploy и пользователя helper_owner.
Без флага --production команды относятся к базе разработки.

При обновлении остановить app/gateway/https, пересобрать образ, выполнить одноразовый
migrate, затем запустить стек. Не запускать несколько миграторов одновременно.
Пароли deploy/.env нельзя менять без смены пароля роли в существующей БД.
Для восстановления создать новую БД владельцем helper_owner, применить доверенный
pg_restore, проверить данные и выдать права helper_app. Не удалять старую БД до приёмки.
Переключение целевой базы требует согласованного изменения DATABASE_URL в профиле.

## Выполненная локальная проверка

Собран Docker-образ, выполнены миграции, app и db healthy. Проверены HTTPS с доверием
к экспортированной локальной CA, создание/чтение записи, изоляция двух сессий.
Подтверждены helper_app, отсутствие SUPERUSER и отказ CREATE TABLE.
Для повторения: скопировать локальный root.crt из Caddy (не устанавливать в системное
хранилище без необходимости) и выполнить:
`python scripts/deploy_smoke.py https://localhost:18443 --ca tmp/deploy-root.crt`.
Скрипт создаёт тестовую запись и две сессии, поэтому на публичном сервере запускать
как осознанный приёмочный прогон. С публичным доверенным сертификатом --ca не нужен.
