# Docker: ошибка загрузки образов EOF

`failed to fetch oauth token: ... auth.docker.io/token: EOF` означает,
что Docker не получил ответ сервера авторизации. В этом случае загрузка образа
ещё не завершена. Сообщение `No such image: caddy` после прерванной загрузки
не является отдельной причиной. Python CalledProcessError сообщает отказ Docker.

## Что проверено на компьютере

Первоначально был только образ postgres:18. TCP:443 до auth.docker.io был доступен,
но HTTPS к реестру завершался тайм-аутом, Docker получал EOF. Проверен системный
прокси 127.0.0.1:10809 и запуск с временным пустым Docker config; настройки системы
не менялись. После восстановления сетевого доступа повторный pull прошёл успешно.
Все образы загружены, приложение собрано, deploy-up завершён. Приложение и БД healthy;
HTTP localhost:18080, сессии, сохранение и изоляция проверены. Groq из Docker успешно
обработал текстовую команду. Прямой вызов Groq из Windows всё ещё дал TLS EOF.
Повторная ошибка потребует проверки доступности реестра и действующего прокси.

## Восстановление доступа

1. Проверьте приложение, обслуживающее системный прокси 127.0.0.1:10809.
   Если этот прокси нужен, он должен работать и пропускать HTTPS CONNECT.
2. В Docker Desktop → Settings → Resources → Proxies проверьте активный режим
   и адрес прокси. Он должен соответствовать вашей рабочей сетевой конфигурации.
   Изменения примените через Apply & Restart. Не удаляйте данные Docker.
3. Проверьте загрузку одного публичного образа:

```powershell
docker pull nginx:stable-alpine@sha256:47928bf67eb62a1863cb08d9ecb52d3e704304ba614eaee17884204677702951
```

4. После успешной загрузки выполните `python dev.py deploy-up`.
   При первом запуске также потребуется доступ к Python/uv-образам и Python-пакетам.

Не удаляйте volumes и не переустанавливайте PostgreSQL: сетевую ошибку это не исправит.
Проверку сертификатов TLS оставьте включённой.

## Временный локальный запуск

Уже установленное окружение и работающий PostgreSQL позволяют запустить интерфейс:

```powershell
python dev.py ai-mode demo
python dev.py serve
```

Откройте http://127.0.0.1:8000. Если этот адрес уже занят запущенным сервером проекта,
используйте существующий сервер и обновите страницу. Для Groq отдельно нужен доступ
к api.groq.com. Обратное переключение: `python dev.py ai-mode groq`.

Документация Docker: https://docs.docker.com/desktop/settings-and-maintenance/settings/#proxies.
