# Текущее состояние

Этапы 1 и 2 выполнены: границы MVP описаны в MVP.md; добавлены таблицы
browser_sessions и entries, миграция 51757401ccab, входная модель NewEntry,
создание/поиск сессии по хешу случайного токена и EntryRepository с обязательным владельцем.
Создание, чтение по ID и ограниченный список доступны на уровне Python.
Транзакцией управляет вызывающий сервис: repository делает flush, но не commit.
ORM обновляет updated_at при изменении записи; прямые SQL-изменения должны задавать его явно.

API пока только инфраструктурный: /, /health/live, /health/ready, /docs.
Cookie, HTTP-авторизация, предметные маршруты, поиск, AI и голос ещё не реализованы.
Изоляция проверена на уровне репозитория; это не PostgreSQL RLS и не готовая HTTP-защита.
Поиск и его индексы добавляются вместе с реализацией этапа 3.

Проверки: python dev.py check (нужна работающая PostgreSQL), python dev.py smoke.
Интеграционные тесты создают случайные схемы test_<uuid> и удаляют только их.
Проверяются чистая миграция, повторный upgrade, downgrade/upgrade, отсутствие расхождения
ORM и миграции, сохранение, откат, фильтрация владельца и ограничения данных.
Следующий шаг: этап 3 — прикладные сервисы и защищённый API четырёх действий.
