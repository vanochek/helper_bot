# Текущее состояние

Этапы 1–4 выполнены; код этапов 5–7 реализован, живая приёмка AI ожидает ключа. Реализованы сессии и записи, миграции, сервис EntryService,
репозиторий с владельцем и HTTP API создания, списка за период и полнотекстового поиска.
Маршруты и примеры — docs/API.md. Поиск использует вычисляемый search_vector и GIN.
Миграция head: d9154c337d4e. Добавлены browser_sessions.draft и chat_messages. Предыдущие применённые миграции сохранены без переписывания.

Сессия задаётся случайным HttpOnly cookie, в БД хранится SHA-256. Изменяющие запросы
требуют точного совпадения Origin с APP_ORIGIN. При HTTPS cookie получает Secure.
Данные не кешируются; чужой ID возвращает 404. Авторизация привязана к браузеру,
не является системой аккаунтов или PostgreSQL RLS; очистка cookie теряет доступ.
Создание подтверждается после commit; ошибка БД возвращает обезличенный 503.

Периоды задаются календарными датами [start,end) в зоне сессии, записи без срока
не включаются. Сортировка пока по времени создания, затем ID; есть limit/offset.
Поиск понимает русские словоформы, но не обещает понимания синонимов или опечаток.
Добавлены текстовый диалог, адаптер OpenAI и атомарная идемпотентность сообщений.
Голос и публичное развёртывание ещё впереди.
Добавлен temporal: относительные даты, недели, UTC-длительности и проверка DST.
POST /api/v1/temporal/resolve использует серверные часы и зону сессии, ничего не сохраняет.
Подробные политики — TIME.md. Свободный текст интерпретируется AI после настройки ключа и модели.
Следующий этап 8: голосовой ввод и озвучивание. Перед живой приёмкой необходимо
настроить OPENAI_API_KEY и OPENAI_MODEL; платные запросы пока не проверены.
Документация диалога, границы и настройка: CHAT.md.

Проверки: python dev.py check, python dev.py smoke, python -m uv run alembic check.
Тесты используют отдельные случайные схемы PostgreSQL. Проверяются миграции,
сохранность, ограничения, HTTP-сценарии, изоляция, Origin, cookie и отказ commit.
