# Даты и время

Модуль temporal принимает структурированный TemporalCandidate, назначение и один
серверный now с часовым поясом. Это детерминированное ядро, а не парсер свободной речи.
Преобразование «завтра в десять утра» в candidate выполняет будущий AI-адаптер этапа 5.
Числа и время в candidate уже нормализованы: local_time=10:00, minutes=120.

| relation | Значение |
|---|---|
| today / tomorrow / day_after_tomorrow | Сегодня / завтра / послезавтра в зоне сессии |
| weekday + weekday=0..6 | Ближайший понедельник..воскресенье; совпадение с сегодняшним днём требует уточнения |
| this_week / next_week | Период с понедельника до следующего понедельника, конец исключён |
| week_end | Воскресенье текущей недели; дедлайн задачи как дата, без выдуманного 23:59 |
| after + minutes | Реальные прошедшие минуты от now в UTC, включая переход DST |
| exact + local_date | Явная календарная дата |

local_time необязателен для конкретной даты; offset в нём запрещён, используется зона сессии.
Задача без времени получает scheduled_on. Встреча и напоминание без времени требуют
уточнения. Неделя для создания записи требует уточнить день. Прошедшие даты остаются
прошедшими: is_past=true, автоматического переноса в будущее нет. Этот флаг должен
учитываться будущим диалогом; endpoint ничего не сохраняет и не подтверждает создание.

Результат: resolved с датой/моментом или периодом; needs_clarification с вопросом,
без выбранного наугад момента. Интервалы календаря возвращают локальные даты и UTC-границы.
При переходе DST несуществующее время и двукратное время требуют уточнения. Для
двукратного времени пользователь может указать точный offset-aware момент через
существующий API записей. Полночь проверяется тем же способом; пропущенная локальная
дата или неоднозначная граница не подменяются молча (список за такой период: HTTP 422).

API: POST /api/v1/temporal/resolve; нужны cookie и допустимый Origin.
```json
{"candidate":{"relation":"tomorrow","local_time":"10:00"},"purpose":"meeting"}
```
purpose: task, reminder, meeting, period. now и timezone от клиента не принимаются:
now берётся сервером один раз, timezone — из текущей сессии. Неизвестные поля: 422.
Ответ с уточнением: HTTP 200, status=needs_clarification. Запрос не создаёт запись.
Существующий POST /entries продолжает принимать явную дату или момент со смещением.
Новые поля схемы БД и зависимости для этого этапа не потребовались.
